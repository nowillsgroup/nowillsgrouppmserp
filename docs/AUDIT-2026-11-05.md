# NowillsPMS — Application Audit, 5 November 2026

**Audited commit:** `8e91c9a` (`main`, the merge of PR #13) · **App version:** 7.77.0
(`config/pms.php`) · **Scope:** the whole application — routes, controllers,
services, models, views, migrations, console schedule, permission catalogue and
repository hygiene.

**Verdict: 4 defects found and fixed (1 cross-tenant, 3 lower severity), 0 open
defects, 23 checks blocked by the absence of a runtime in this environment
(listed in §5).** Nothing in this report
rests on a grep count alone: every finding was opened, read and reproduced.

Unlike the 26 October audit (`docs/AUDIT-2026-10-26.md`), this pass had **no PHP
binary, no database, no `vendor/` autoloader and no HTTP server** available. It is
therefore **entirely static** — the runtime layers (full GET sweep, `config:cache`,
`route:cache`, migration execution) could not be repeated here and must be re-run
on a machine with the application installed. §1 states exactly what was covered
and what was not; nothing below claims a page was fetched.

## 1. How the audit was run

| Layer | What it did | Tool |
|---|---|---|
| **PHP syntax** | Parses all **983** PHP files under `app/`, `config/`, `database/`, `routes/`, `tests/` with php-parser and fails on a parse error. | `deploy/dev/audit/php_syntax_check.js` |
| **Routes** | Walks both route files as an AST, resolves namespace/`use` aliases, expands controller-scoped and nested groups, `Route::resource`, fluent registrations (`Route::middleware(…)->post(…)`) and loop-generated names (`foreach ([…] as $a) … ->name($a)`), then checks every referenced controller class and method exists and that no route name is duplicated. | `deploy/dev/audit/routes_integrity_check.js` |

| **Blade** | Extracts and parses every PHP expression Blade compiles: `@php … @endphp`, `{{ }}`, `{!! !!}`, `@if/@elseif/@unless/@while/@foreach/@forelse/@switch/@case/@json/@checked…`. Directive arguments are read with a balanced-parenthesis scanner, not a regex. | `deploy/dev/audit/blade_syntax_check.js` |
| **Schema** | Replays the migration order statically: no table created twice, no `Schema::table()` before its `Schema::create()`, every migration has a `down()`. | `deploy/dev/audit/application_health_check.py` |
| **Models** | Every `belongsTo/hasMany/hasOne/belongsToMany/morphMany/morphTo/hasManyThrough(Foo::class)` target exists; every hotel-scoped table's model uses the `BelongsToHotel` trait. | `application_health_check.py` (plus an ad-hoc pass over the 404 hotel-scoped tables) |
| **Console** | Every `Schedule::command('…')` is a declared command signature; no command registered twice. | `application_health_check.py` |
| **Permissions** | Every permission the app asks for (`perm:` middleware, `can_do()`, `hasPermission()`, sidebar `'perm' =>`) is granted by at least one standard role, and every granted token is actually checked somewhere. | ad-hoc pass over `HotelProvisioner::ROLES` (§4.6) |

`php-parser` is the only dependency the new checks add. It is resolved from
`$PHP_PARSER_PATH`, `./node_modules` or `/tmp/phpcheck`; when it is missing the
four JS checks print `SKIP` and exit 0 rather than failing the run for an
unrelated reason. All four were validated by injecting a deliberate fault (a
syntax error, an unregistered route name, a missing icon) and confirming they
fail, then reverting.

**Not covered here** (needs a live install): every HTTP flow, `route:cache` /
`view:cache` / `config:cache` builds, migration execution against MySQL, queue and
scheduler behaviour, and the PHPUnit suite (see §5.2).

## 2. Defects found and fixed

### 2.1 MEDIUM — the demo seeder could not be compiled at all

`database/seeders/DatabaseSeeder.php:24`

```php
throw new \\RuntimeException(          // before — two backslashes
throw new \RuntimeException(           // after
```

`\\RuntimeException` is not a class reference in PHP: the second backslash is an
unexpected token, so the **whole file fails to compile**. `php artisan db:seed`
therefore died with `Parse Error : syntax error, unexpected '\' (T_NS_SEPARATOR)`
instead of the intended message — and, more importantly, the production guard that
refuses to seed synthetic demo records never got the chance to run, because the
guard lives in the same file. Fixed; the fixed file is what the shipped
`composer setup` script (`migrate --seed`) now compiles.

Verified: `node deploy/dev/audit/php_syntax_check.js` reports 983 files parsed,
0 syntax errors, and reports this exact error against a reproduction file.

### 2.2 LOW — six icons asked for by the interface did not exist

`resources/views/partials/icons.blade.php`

`<x-icon name="…">` renders `<use href="#i-…">`. Six names used by the views had no
`<symbol>` in the sprite, so those buttons and headers rendered with a **blank
space where the icon belongs** — silently, since a missing SVG symbol raises
nothing:

| Missing symbol | Where it was used |
|---|---|
| `external` | payroll payslip "open" link |
| `info` | AP bill view, blocks/form |
| `list` | shifts index |
| `settings` | loyalty index, recreation outlet |
| `truck` | rentals index, rentals fleet |
| `upload` | my documents, settings → migration |

Additions follow the existing 24×24 stroke style (`stroke: currentColor`,
`stroke-width: 1.8` from `public/css/app.css`), so no stylesheet change was
needed. The sprite is now 68 symbols; every static usage, every `'icon' =>` value
in `config/pms.php` (33) and every model icon map (`Activity::ICONS`,
`ConciergePlace::ICONS`, `Conversation::CHANNEL_ICONS`,
`ReservationWorkspaceService::AMENITY_ICONS`) resolves.

### 2.3 MEDIUM — a forged report schedule could mail one property's report to another property's staff

`app/Services/ReportScheduleService.php:336`

```php
$users = User::whereIn('id', array_map('intval', (array) ($d['recipient_users'] ?? [])))
    ->where('is_active', true)->get();                       // before
$users = User::visibleToHotel()
    ->whereIn('id', …)->where('is_active', true)->get();      // after
```

`User` is the only model without a global hotel scope (authentication has to
resolve a user before a tenant exists — §4.5), so a staff query must carry the
filter itself. `KpiService::saveAlert()` already does this (`User::visibleToHotel()`
at line 211); the report-schedule path did not. The recipient ids come straight from
the submitted form, and the only remaining validation was “has an e-mail, holds the
report permission, domain allowed” — a staff member of *another* property who holds
`reports.view` passes all three. The schedule is then stored and, at send time,
`ReportSchedule::recipients()` reads the same ids and mails the report — hotel A's
occupancy, revenue and guest figures — to hotel B's employee.

Reaching it needs a forged POST from someone allowed to manage report schedules
(which is why this is MEDIUM, not HIGH), and the result is cross-tenant disclosure
rather than unauthorised access. Fixed by scoping the lookup the same way
`KpiService` does; group administrators who oversee the property remain eligible,
since `visibleToHotel()` includes them.

It went unnoticed because rule 7b of `system_audit.php` accepted the *string*
`recipient_users` as proof of tenant scoping — and `$d['recipient_users']` contains
it. The rule now exempts only the stored attribute (`$this->recipient_users`), not
the request array, and the same rule ships as an executable check in
`application_health_check.py` (§6). Verified by reverting the fix: the check fails
with four hits, including line 336; restoring the fix makes it pass.

### 2.4 LOW (harness — not application code) — three stale assertions

`deploy/dev/audit/reservation_detail_modal_accessibility_check.py` asserted the
exact wording of the split-tender labels (`<label for="advanceAmount$ {i}">Amount</label>`).
The labels were reworded during the POS tender work, so the check failed while the
markup was correct. It now pairs each generated control with *a* label bound to its
generated id, requires the text to be non-empty and unique across the controls, and
keeps the `aria-label` assertion. The accessibility guarantee is unchanged; the
wording is no longer frozen. 6/6 tests pass.

## 3. Tooling defects found and fixed

The route audit carried two blind spots from the previous round, both now fixed and
covered by the committed script:

| Blind spot | Consequence before | Now |
|---|---|---|
| `Route::resource(...)` not expanded | 24 framework-generated routes invisible (guests, users, roles, crm segments) | names expanded the way Laravel does, honouring `->only()`/`->except()` |
| `->name($a)` inside `foreach ([…] as $a)` | 6 housekeeping routes (`hk.start`, `hk.dnd`, `hk.complete`, `hk.minibar`, `hk.issue`, `hk.found`) invisible | loop variable resolved from its literal array |
| Fluent `Route::middleware(…)->post(…)` | 1 permission-gated POST (`owner.queries.close`) invisible | chain read from the verb step, not only from `Route::<verb>` |
| `system_audit.php` rule 7b accepted the bare string `recipient_users` as tenant scoping | the request array `$d['recipient_users']` passed the rule, which is how §2.3 survived | only the stored attribute `$this->recipient_users` is exempt; the same rule now also runs in `application_health_check.py` |

Route coverage went from **2,070** to **2,100** routes, all named, all resolutions
clean. The Blade audit's earlier "7 syntax failures" were extractor artefacts, not
defects — see §4.1.

## 4. Reviewed and dismissed (reported with the reason)

### 4.1 `resources/views/frontdesk/checkout.blade.php:95` — **false positive**
Reported last round as a missing space (`@if(can_do('desk.wakeup'))booked (`). It is
valid Blade: the `@if` closes at that parenthesis and `booked (` is literal text.
The regex that flagged it was matching to the *next* `)` on the line. The rewritten
audit reads directive arguments with a balanced-parenthesis scanner and reports
**42,229 expressions across 830 views, 0 syntax failures**.

### 4.2 `route('report')` / `route('token')` — **false positives**
Both are `$request->route('report')` and `$r->route('token')` — request-parameter
lookups, not URL generation. The reference check excludes `->route(`.

### 4.3 `MarketingMail::renderBody()` — bold markers applied after linkification
`**bold**` is converted after URLs become `<a href>`, so a `**` pair inside a URL can
inject `<b>` into the attribute value. The text is passed through `e()` first, so
`"` and `<` are already entities and the attribute cannot be broken out of — this is
markup noise, not an XSS. No change made; noted so it is not re-reported as new.

### 4.4 303 `{!! !!}` raw echoes — all reviewed, none user-controlled
They are `status_badge()`, `tr_badge()`, `stars()`, `paper_chip()`, QR SVG, generated
`<option>` markup, and `nl2br(e(…))` for multi-line text. The two markdown renderers
also sanitise: `SopDocument::render()` uses `Str::markdown(…, ['html_input' => 'escape', 'allow_unsafe_links' => false])`,
`MarketingMail::renderBody()` escapes first (§4.3).

### 4.5 `App\Models\User` does not use `BelongsToHotel` — deliberate
404 hotel-scoped tables have models, and every one of those models uses the trait;
`User` is the single exception, because authentication must resolve a user before a
tenant exists. The class documents it and offers `scopeVisibleToHotel()`. Of the 80
`User::` queries in application code, every staff-facing one filters explicitly — the
exceptions are console commands (no tenant), login by group id (pre-tenant), and
stored recipient lists that were validated when saved. One request-fed list was *not*
validated: see §2.3, now fixed.

### 4.6 Permission catalogue — 290 required, 262 granted, no gaps either way
Every permission token requested by `perm:` middleware, `can_do()`,
`hasPermission()` or the sidebar registry is granted by at least one of the 28
standard roles; every granted token is checked somewhere in the code. No dead menu
entry, no orphan grant. `service_shift.waiter_required` is intentionally both a
setting listed in `config/pms.php` and a permission granted to `Restaurant Waiter`
— it gates *whose* POS entry requires an open service shift.

### 4.7 69 MB of dependencies tracked under `build/`
8,899 of the repository's 11,120 tracked files live in `build/vendor`. This is by
design: `composer.json` sets `"vendor-dir": "build/vendor"` and the CyberPanel/cPanel
deploy scripts, `bootstrap/app.php` and the dev harnesses all read from there, so the
project ships without a composer step on shared hosting. Left as-is; noted because
it dominates clone size.

### 4.8 Other sweeps that came back clean
`env(` outside `config/`: **0**. `dd/dump/var_dump/var_export/xdebug_break` in
`app/` and `routes/`: **0**. Hard-coded credential literals: **0** (the new secret
rule ignores validation rules and route constraints — those were the only hits).
`.env` tracked: **no**. Raw SQL with interpolated input: 2 sites
(`BusinessDevService::marketMix()`, `CrmService::journeyCandidates()`), both
interpolate a value chosen by a `match()`/ternary over literals, not request input.
Closure route actions: **0** (so `route:cache` stays buildable). Scheduled commands:
29 entries, 32 declared signatures, none missing, none duplicated.

## 5. Not verified — needs a runtime, not a fix

### 5.1 Twenty-three harnesses blocked by the environment
21 of the 140 audit harnesses need the application served on
`127.0.0.1:8004` (or a `php artisan route:list` dump at `/tmp/routes.json`), and 2
need a PHP runtime to introspect the live menu and document facts:

`ap_fx_flow`, `ap_fx_pay_flow`, `bank_import_flow`, `channel_e2e`,
`channel_fx_flow`, `channel_manager_http_check`, `flows_a`, `flows_b`, `flows_e`,
`full_get_sweep`, `http_sweep`, `hr_bonus_flow`, `hr_paternity_flow`, `hr_paye_flow`,
`hr_tax_cases`, `main_dashboard_links_http_check`,
`rate_contract_detail_http_check`, `reservation_dashboard_links_http_check`,
`reservation_room_board_http_check`, `roster_save_flow`, `vat_registration_flow`
(HTTP → `Connection refused`), plus `gap_audit_check` and `modules_doc_check`
(require PHP). They are **not** failures of the code; they are unrun.

Run them on a machine with the app installed:

```bash
deploy/dev/bin/php artisan serve --port=8004        # terminal 1
deploy/dev/bin/php artisan route:list --json > /tmp/routes.json
python3 deploy/dev/audit/full_get_sweep.py
python3 deploy/dev/audit/http_sweep.py
```

### 5.2 `docs/TEST-STATUS.md` refers to a suite that is not in this repository
`TEST-STATUS.md` documents a 651-test PHPUnit run (GitHub Actions 37752732099,
commit `d857feb`, 8 October 2026). This checkout has **no `tests/` directory, no
`phpunit.xml` and no `.github/workflows/`**, while `composer.json` still requires
`phpunit/phpunit`, `mockery` and `collision` and exposes `composer test`. The
historical result is accurate for that commit; what is missing is the ability to
reproduce it from the current tree. Recommended before the next release: restore
the suite (or re-point `TEST-STATUS.md` at the `deploy/dev/audit` harnesses that do
ship here). Not changed in this pass — restoring a test suite is development work,
not an audit fix.

### 5.3 Deployment / runtime assertions
No deployment, migration, queue or scheduler action was performed. The production
server is untouched. Production deployment remains manual.
