## 1. What this repository is

Nowills PMS / ERP — multi-property hotel PMS (Ghana): front office, reservations, POS/KDS, accounts,
night audit, VAT/GRA E-VAT, channel manager, booking engine, guest portals, offline-first
housekeeping/POS/front-desk, B2B partner & organiser portals, licensing-as-a-service enforcement.

- Single squashed commit (`cf6ef58`) — the repository has no usable history (see §5.6).
- Stack: PHP 8.3+, Laravel 13 (`v13.33.0`), MySQL/MariaDB, Blade views, vanilla JS, no build step.
- Multi-tenancy: enforced in code (`BelongsToHotel` global scope on 413/434 models; remaining
  21 are child/pivot rows reached via scoped parents, plus platform-level `User`/`Role`/`Hotel`).
- Deliberately bypasses Composer on the server: `composer.json` sets `vendor-dir` to `build/vendor`,
  and `build/vendor` is **committed to Git** (8,899 files, 72 MB) so cPanel hosts need no Composer.
- A full WASM-PHP dev/audit runtime lives in `deploy/dev/` (746 files, 39 MB), including 174
  preview HTML snapshots and an "attack the app" harness. It is committed.

**Low** = correctness/hygiene worth fixing, limited impact. **Info** = note for the record.

## 3. Security findings

### 3.1 HIGH — the service worker writes authenticated admin pages into the browser cache

`public/sw.js` — every same-origin request with `mode === 'navigate'` (i.e. **every page load in the
app, signed-in or not**) is served `networkFirst(request, FALLBACK)`, which on success calls
`cacheIfUsable()`. That function checks only `response.ok` and `response.redirected`:

```js
async function cacheIfUsable(request, response) {
  if (!response || !response.ok || response.redirected) return response;
  const cache = await caches.open(CACHE);
  await cache.put(request, response.clone());   // ← cached unconditionally otherwise
}
```

`cacheIfUsable` does **not** honour the `Cache-Control: no-store, private` header that
`SecurityHeaders` sets for authenticated requests (`app/Http/Middleware/SecurityHeaders.php`,
`if ($request->user()) { $h->set('Cache-Control', 'no-store, private'); }`) — even though the
service worker's own header comment claims *"a no-store response must never become the offline copy
of a screen."*

**Impact.** On the shared PCs this product targets (front desk, kitchen, kiosk back office), pages
containing guest PII (names, room numbers, folios, balances, ID-pour details) are persisted in the
browser's Cache Storage and survive sign-out and session expiry. Any later user of the same browser
profile can read them via DevTools → Application → Cache Storage.

**Fix (small).** Skip caching whenever the response forbids it, and restrict offline caching to the
offline workspaces that are designed for it:

```js
async function cacheIfUsable(request, response) {
  if (!response || !response.ok || response.redirected) return response;
  const cc = (response.headers.get('Cache-Control') || '').toLowerCase();
  if (cc.includes('no-store') || cc.includes('private')) return response;
  // …existing code
}
```

### 3.2 MEDIUM–HIGH — `trustProxies(at: '*')` makes the client IP spoofable

`bootstrap/app.php:23` sets `$middleware->trustProxies(at: '*')`. Laravel then believes
`X-Forwarded-For` / `X-Forwarded-Proto` from **any** sender. In this codebase the client IP is a
security input in at least three places:

1. **REST API key IP allow-list** — `ApiService::ipAllowed()` (`app/Services/ApiService.php:174`)
   refuses keys used from unexpected addresses. With a spoofed `X-Forwarded-For`, that control is
   gone, leaving only the bearer hash.
2. **Per-IP rate limiters** — login (`throttle:10,1`), public token endpoints, `api-bad-token:*`
   (`ApiAuthenticate`), kiosk/TV limiters. Rotating the header resets every counter.
3. **Audit trail** — `ActivityLogger`/`ApiRequestLog` record `$request->ip()`; forged IPs poison
   forensic evidence (the PMS relies on this log for incident response).

HSTS is likewise gated on `$request->isSecure()`, which is derived from `X-Forwarded-Proto` when
proxies are trusted — see `SecurityHeaders.php`.

**Why it probably "works" today:** cPanel/LiteSpeed usually *sets* `X-Forwarded-*` itself, so the
wildcard looks convenient. But the moment the app is reachable directly (origin IP, wrong vhost,
or a front proxy that passes client headers through), all of the above fail open.

**Fix.** Trust only the real front proxies, e.g. `trustProxies(at: '127.0.0.1,10.0.0.0/8')` (ask
the host which IPs LiteSpeed/Apache use), or `at: env('TRUSTED_PROXIES', '127.0.0.1')` with the
value documented in `.env.example`. Confirm the server strips client-supplied `X-Forwarded-*`.

### 3.3 MEDIUM — cross-tenant staff directory disclosure (Budget variance)

`app/Http/Controllers/BudgetController.php:357`:

```php
'people' => \App\Models\User::orderBy('name')->get(['id', 'name']),
```

This is on the authenticated budget-variance screen. `User` is intentionally **not** globally
scoped, and there is no hotel filter here: every staff member on the **entire installation**
(all tenants, all groups) is serialized into the page for the "assigned to" dropdown — unbounded
query, cross-tenant disclosure of internal user IDs and names. The sibling action
(`explain()`) validates submissions with the tenant-aware `owned:users` rule, so foreign users
cannot actually be *assigned*; the exposure is the listing itself.

**Fix.** `'people' => \App\Models\User::visibleToHotel()->orderBy('name')->get(['id','name']),`
(the `scopeVisibleToHotel` scope already exists on the model). Flagged by
`application_health_check.py::StaffQueryIsolationTest` — the remaining 7 `User::` hits it reports
were individually reviewed and are correctly group/hotel-scoped or group-scoped counts
(`HotelGroup::userCount`, `seatsReleased`, `GroupPeopleService::people/activeGroupAdmins`,
`PropertyController::grantCandidates/accessRow`).

### 3.4 MEDIUM — the cPanel package ships internal audit reports and the dev/attack runtime

`deploy/package-cpanel.sh` is well-built in most respects (git archive, dirty-tree refusal,
secret checks, installer injection), but:

- Its exclude list references `docs/AUDIT-REPORT.md`, which **does not exist**. The actual audit
  reports — `docs/AUDIT-2026-10-26.md`, `docs/AUDIT-2026-11-05.md`,
  `docs/NOWILLS-PMS-CODEBASE-AUDIT-2026-10-20.md`, `docs/DATE-STORAGE-AUDIT.md`,
  `docs/FEATURE-GAP-AUDIT.md`, `docs/FRONT-OFFICE-AUDIT.md`, `docs/HR-WORKFORCE-AUDIT.md` —
  enumerate weaknesses and attack surfaces, and **are included** in the ZIP.
- `docs/screenshots/**` is excluded but does not exist either (`docs/` is 565 KB total) — a stale line.
- `deploy/` (39 MB) is included: the WASM-PHP dev runtime, `deploy/dev/audit/` (≈100 Python/PHP/JS
  scripts whose explicit purpose is to probe and attack the app, e.g. `tinker.php` with
  `eval($code)`, `ap_fx.php` shelling out to curl), 174 preview HTML snapshots (32 MB) of live
  screens with demo data, and `deploy/dev/serve.mjs` with a default `PMS_DEV_PASS = Admin@123`.

**Impact.** Every shared/cPanel server this product installs on carries a map of its own
vulnerabilities plus the tooling to probe it, readable by anyone with file access to the docroot
(or any other tenant on the same shared host — exactly the "no SSH, neighbour-tenant" threat model
this packaging targets).

**Fix.** Exclude `docs/AUDIT-*.md`, `docs/*AUDIT*.md` (or all of `docs/` and keep only
`docs/INSTALL-CPANEL.md`/`MODULES.md` as intended), and all of `deploy/` except
`deploy/installers/*.php.txt` (which the script already copies). Update the stale exclude names.

### 3.5 LOW — `PropertyController::grant` does not scope `user_id`

`grant()` validates `user_id` as `exists:users,id` only (`PropertyController.php:398–404`).
`PropertyService::grantAccess` blocks users belonging to a *different group* and rejects
self-grants, but:

- a user with `hotel_group_id = NULL` whose **home hotel sits in another group** can be granted
  access and is then silently adopted into the caller's group (`PropertyService.php:242–244`);
- the UI picker (`grantCandidates`) offers exactly that set, so this is partly by design — but the
  endpoint should re-apply the same rule it renders, not a wider one.

**Fix.** Replace `exists:users,id` with a validation rule matching `grantCandidates`
(`whereIn hotel_id IN caller-group hotels OR hotel_group_id = caller group OR hotel_group_id IS NULL`).

Also note `role_id` is checked via `Role::whereKey($roleId)->exists()` inside the service — with the
tenant global scope this means "role of the current hotel", which is correct; keep it.

### 3.6 LOW — missing `cart` icon (blank render)

`resources/views/partials/icons.blade.php` defines 68 `i-*` symbols — **no `i-cart`**. Views that
use it: `resources/views/procurement/grns.blade.php:5` (`<x-icon name="cart"/>`), `:70` (`x-stat
icon="cart"`), `resources/views/inventory/purchases.blade.php:12,27` (`x-stat icon="cart"`). The
stat component expands to `<x-icon :name="$icon"/>`, which emits `<use href="#i-cart">` — nothing
renders. Flagged by `icons_reference_check.py` (it reports the x-icon use; the x-stat path was
confirmed by reading both components).

**Fix.** Add an `i-cart` (shopping-cart) symbol to the sprite.

## 4. Tests and CI — the structural gap

- **This repository contains no `tests/` directory and no `phpunit.xml`.** `composer.json` declares
  an autoload-dev PSR-4 mapping for `Tests\` and a `test` script calling `php artisan test`, but
  there is nothing to run; `.htaccess` even pre-blocks a `tests/` path that does not exist.
- `docs/TEST-STATUS.md` documents **651 passing tests** — at commit `d857feb` (8 Oct 2026), executed
  on an external GitHub Actions environment (`nowillsgroup/NowillsPMS-ERP`), not reproducible from
  this checkout. It cannot serve as a regression gate for `cf6ef58`.
- `.github/` does not exist in this tree. No static checks run on push; the only gates are the
  ad-hoc `deploy/dev/audit/*.py|*.js` scripts, which are strong but unenforced and environment-fragile.
- `composer.lock` pins Laravel `v13.33.0`, phpunit `12.5.36`, pint `1.32.1`, faker `1.24.1` — no
  obviously abandoned packages, but **no vulnerability audit was run** (Packagist unreachable from
  this sandbox). Treat dependency freshness as unverified.
- Git history is a **single squashed commit**; nothing can be bisected and PR-level review is lost.

**Fix.** Vendor the test suite into this repository (or make CI clone/attach it), add
`.github/workflows/ci.yml` running: php-parser syntax gate, routes integrity, blade syntax, icons,
`application_health_check.py`, `composer audit`, and PHPUnit against MySQL 8. Gate merges on it.

Resource estimate for the suite to matter: even 50–100 high-value feature tests (login/lockout,
tenant isolation of top 20 screens, folio charge/settle, night audit close) would outweigh any
other remediation in this list.

## 5. Repository hygiene & packaging

**5.1 `build/vendor` (72 MB, 8,899 files) is committed** — intentional (no-Composer cPanel installs),
and the package script relies on it. Costs: every clone/search/diff carries third-party code;
and the production ZIP ships **dev** packages — `phpunit/phpunit 12.5.36`, `laravel/pint` (incl. a
tracked 3.7 MB compiled binary `build/vendor/laravel/pint/builds/pint`), `fakerphp/faker`,
`mockery/mockery`, `laravel/pail`, `nunomaduro/collision`. Recommendation: keep committed prod deps
if the no-Composer contract must hold, but **install with `--no-dev` for the release build** (or
maintain a separate `build/vendor` that is a release artifact, not a development convenience).

**5.2 `deploy/dev/` (39 MB, 746 files) is committed** — WASM-PHP runtime, 174 preview HTML
snapshots (32 MB) of real screens, ~100 audit-harness scripts (several of which attack the app),
simulators with demo credentials. Fine as a development environment; wrong place for a release
payload — see §3.4. Recommend moving to a tooling branch/repo or at minimum excluding from Git
archives.

**5.3 Version drift (stale shipped artifacts):**
- `config/pms.php` → `7.77.0`; README documents features through **v7.78**; 
- `START-HERE.txt` → **7.54.0** ("Built from commit 103c96a");
- `public/download-cpanel.html` → advertises **v7.54.0**, links `/nowills-pms-cpanel.zip` (which is
  not in the repo; 404s on a fresh deploy);
- `public/docs/INSTALL-CPANEL.md` → "Version 7.54.0", differs from `docs/INSTALL-CPANEL.md` (7.77.0).
The package script regenerates `START-HERE.txt` at build time (good), but the committed copies lie
about what this tree is.

**5.4 Stale files served from the web root:** `public/download-cpanel.html` (distribution page,
stale), `public/docs/INSTALL-CPANEL.md` (duplicate of docs, stale), `public/favicon.ico`
(0 bytes — browsers requesting `/favicon.ico` get an empty 200). Remove or regenerate them; the
docroot should carry only what the app serves.

**5.5 `.env.example` ships dev-unsafe defaults** (`APP_ENV=local`, `APP_DEBUG=true`,
`DB_PASSWORD=change_me`, `LOG_LEVEL=debug`) and omits `SESSION_SECURE_COOKIE`. The web installer
writes `APP_ENV=production, APP_DEBUG=false, LOG_LEVEL=error` (verified), so the *installer* path is
safe — but anyone who `cp .env.example .env` on a server gets debug mode and the demo-login banner
(`resources/views/auth/login.blade.php` prints demo credentials when `app()->environment('local')`).
Recommend flipping the template to `APP_ENV=production`, `APP_DEBUG=false`, and documenting
`SESSION_SECURE_COOKIE=true` for HTTPS installs.

**5.6 Single squashed history.** Every file in the repo is in one commit; `git log -p` is useless
for forensics and `git bisect` cannot work. Preserve real history going forward (merge commits or
rebased feature branches, squash only within a PR).

**5.7 `.gitattributes`** has no `export-ignore` list. The package script uses explicit `git archive`
excludes instead (acceptable, but fragile — see 3.4). `*.mt940 -text` is correctly exempted (bank
fixtures are byte-exact).

**5.8 `robots.txt`** is `User-agent: *` + empty `Disallow:` — everything, including `/login`,
`/Administration`, `/reports`, is crawlable. For a back-office that hands out demo credentials in
`local`, disallow `/` except any genuinely public booking paths.

**5.9 `.gitignore` is otherwise solid** — `.env*`, `*.zip`, `public/install.php`, `storage/framework/installed.lock`,
backup dirs and uploads are all excluded; no `.env` is tracked; no keys/certificates/dumps are tracked;
`docs/examples/migration/*.csv` contain clearly fictional PII (reserved 555 numbers, `example.com`).

## 7. What was checked and is clean

Positive controls verified during this audit (not exhaustively, but on the risky paths):

- **No committed secrets.** Pattern scan for AWS/PEM/Slack/GitHub/Stripe/private-key material: 0 hits.
  No `.env` tracked. Installer templates are `.php.txt` (never web-executable) and are gitignored at
  live paths.
- **Multi-tenancy.** `BelongsToHotel` global scope (413/434 models; exceptions are child/pivot rows
  reached only through scoped parents — verified `pos_order_items` is filtered via `whereHas('order'…)`
  wherever queried directly); tenant middleware prepended before route-model binding; group-admin
  escape hatch is explicit; `HotelProvisioner` provisions per-hotel roles.
- **SQL injection.** 405 raw-expression uses reviewed: all are static strings or constant-derived
  (`$sign = $type === 'income' ? 'credit - debit' : 'debit - credit'` with both call sites passing
  literals); dynamic values use bindings. No interpolation into raw fragments found.
- **XSS.** Blade `{!! !!}` uses are `status_badge()` (escapes via `e()`), generated QR SVGs, or
  `nl2br(e($x))`; the sprite escapes `use href` targets. `@json` used for JS payloads. Client JS
  escapes before `innerHTML` consistently (verified `offline-*, kiosk.js, fleet-live.js`).
- **AuthN.** Login has a timing-equaliser hash check, 5-strike lockout (15 min), 2FA TOTP with
  encrypted secrets, session regeneration on login/2FA, `is_active` checks, generic error messages,
  throttled endpoints, and a residential "locked due to failed attempts" UX message.
- **AuthZ.** `RequirePermission` gate + `can_do()` + licence enforcement (`LicenceSurface` global
  middleware, `config/licence.php` surface map) agree with each other; 33 authenticated routes lack
  `perm:` gates — all reviewed: logout, profile, 2FA management, search, notifications, offline
  workspace, briefings (per-pack `BriefingService::can` checks inside the controller). All intentional.
- **REST API.** Bearer keys `nwp_<8>_<40>` stored as SHA-256 + `hash_equals` compare, per-key rate
  limit, IP allow-list, scope middleware, per-hotel licence check, full request logging including
  refused calls, `no-store` responses, `/api/v1` always emits structured JSON errors.
- **Webhooks.** Payment webhooks verify per-gateway HMAC (`SignatureException` → 401 +
  `signature_ok=false` event); payloads redacted (`card`, `account_number`, contacts) before
  persistence; duplicate delivery replay protection via `event_id` + unique constraint.
- **Uploads.** All user uploads validated (`image|mimes|max`), written to random
  `Str::random`/`bin2hex(random_bytes())` names, no user-controlled path components; whole-of-string
  extension checks.
- **Installer** does not seed the demo database; creates only the property + administrator the user
  entered; locks itself afterwards; writes production `.env`.
- **Static gates pass** (see the table at the top): 1,046 PHP files parse, 874 Blade files / 50,161
  expressions compile clean, 2,185 routes all resolve to real controller methods, 6,422 route/view
  references resolve, only 1 icon defect.

## 8. Limitations (what this audit did NOT do)

- No PHP runtime: `php -l` parity was established with php-parser, not PHP itself; nothing was
  executed; migrations were replayed statically, never against MySQL/MariaDB; HTTP behaviour
  (headers, CSP in practice, cache headers) was read from code, not observed.
- `composer audit`/`composer validate` could not reach Packagist; vulnerability status of the 111
  locked packages is unverified.
- The 651-test suite cited in `docs/TEST-STATUS.md` is not in this repository and was not run.
- Frontend JS was reviewed by reading; no browser/DOM execution.
- `build/vendor` (third-party code) was inventoried, not audited line-by-line; `pint`/`phpunit`
  binaries were not executed (they are not run at install time).
- Business-logic correctness beyond spot checks (accounting identities, night-audit invariants) was
  out of scope for an all-files audit.
